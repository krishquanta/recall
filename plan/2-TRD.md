# TRD — Technical Requirements Document
> **Technical requirements, constraints, integrations, and performance**

---

## Functional Requirements

- **FR-1** The system SHALL accept files ≤ 50 MB per upload. Supported types: `.pdf`, `.md`, `.txt`, `.xlsx`, `.csv`, `.png`, `.jpg`, `.jpeg`, `.webp`, `.heic`.
- **FR-2** Extracted text SHALL include `{doc_id, page_or_row, chunk_index, char_start, char_end}` metadata per chunk.
- **FR-3** Embeddings SHALL be computed using `text-embedding-004` (768-dim) via Google Gemini API.
- **FR-4** LLM answers SHALL be generated by `gemini-2.0-flash` with a system prompt enforcing citation tags.
- **FR-5** Hybrid search SHALL combine BM25 keyword score + cosine similarity with configurable α weight.
- **FR-6** The UI SHALL render clickable citation chips that open the source page in a preview panel.
- **FR-7** Processing status SHALL update via Server-Sent Events (SSE) in real time.
- **FR-8** Image files (PNG/JPG/WEBP/HEIC) SHALL be transcribed via **Gemini Vision** multimodal API, supporting printed text, handwritten notes, whiteboard photos, and mixed content.
- **FR-9** PDFs that yield fewer than 50 characters of extracted text (i.e. scanned/image-only PDFs) SHALL automatically fall back to Gemini Vision page-by-page OCR.

## Non-Functional Requirements

| Requirement | Target |
|-------------|--------|
| Availability | 99.5 % (single-node dev target) |
| Scalability | Support ≥ 100 documents, ≥ 500 chunks each |
| Security | Files stored locally; no third-party cloud storage in v1 |
| Accessibility | WCAG 2.1 AA for all interactive UI elements |
| Offline-first | Core UI functional without network (except LLM calls) |

## Technology Stack

| Layer | Technology | Reason |
|-------|-----------|--------|
| Backend runtime | Node.js 20 LTS | Stable LTS, great ecosystem |
| Backend framework | Express + TypeScript | Lightweight, familiar |
| Frontend | React 19 + Vite + TypeScript | Fast HMR, latest React |
| Styling | Tailwind CSS | Utility-first, fast to iterate |
| AI / LLM | Google Gemini API (`gemini-2.0-flash`) | Free tier, excellent citation following |
| Embeddings | `text-embedding-004` (768-dim) | Same API key, no extra cost |
| Handwriting OCR | Gemini Vision (multimodal) | Same API key, best handwriting quality |
| PDF parsing | `pdf-parse` | Pure JS, no native binaries on Windows |
| Excel parsing | `xlsx` (SheetJS) | Industry standard |
| Vector store | `vectra` | Local file-based, no Docker needed |
| Full-text search | `minisearch` | BM25-style, pure JS, zero dependencies |
| File uploads | `multer` | Standard Express multipart handler |
| State management | Zustand | Lightweight, TypeScript-friendly |
| PDF viewer | `react-pdf` | Client-side, lazy page rendering |

## Integration Points

```
┌─────────────────────────────────────────┐
│  Browser (React SPA)                    │

```

## Environment Configuration

```env
# backend/.env
GEMINI_API_KEY=your_key_here
LLM_PROVIDER=gemini
LLM_MODEL=gemini-2.0-flash
EMBEDDING_MODEL=text-embedding-004
PORT=3001
UPLOAD_DIR=./uploads
DATA_DIR=./data
```

> [!NOTE]
> The `LLM_PROVIDER` env var is designed to be swappable. Setting it to `ollama` and providing
> `OLLAMA_BASE_URL=http://localhost:11434` will route all LLM calls to a local Ollama instance
> instead of Gemini — useful if you want full offline/private mode in the future.
